## [1.0.0-beta.3] - 2026-11-14

### Minor Changes

- [#123](https://github.com/bielu/bielu.bettersearch/pull/123) [`d1fc094`](https://github.com/bielu/bielu.bettersearch/commit/d1fc09476b4b77e1ed91c8631a361456987daffc) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - `IndexingServiceAsync.IndexMultipleDocumentsAsync` validates the whole batch before indexing any of it, then makes one call to the provider's bulk `IndexMultipleDocumentsAsync` instead of indexing one document at a time. A document the validator rejects now stores none of the batch, where the documents before it used to be stored already, and the error names the document. When the batch fails, the indexing observers get nothing, even for documents the engine stored; they used to get `OnNext` for each document stored before the failure. Every provider now names the documents an engine rejects, in the error's `ids` metadata: Elasticsearch and OpenSearch read each item of the bulk response, so the other documents stay stored, and Elasticsearch returns the real count instead of `0`; Meilisearch and Lifti write each index's documents as one change, so none of that index's documents is stored. Lifti adds each index's documents with one `AddRangeAsync`. Elasticsearch and OpenSearch send each index's documents in bulk requests of at most the new `BulkBatchSize` index setting (1000 by default), so a large import stays under the request size limit.

- [#157](https://github.com/bielu/bielu.bettersearch/pull/157) [`2588bef`](https://github.com/bielu/bielu.bettersearch/commit/2588beff6de45166ca6139202b7b4e9d1e55c31b) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Client settings on every engine provider (#149). Elasticsearch and OpenSearch get `RequestTimeout` and `MaxRetries`, and Meilisearch gets `RequestTimeout`, in `SharedIndexSettings` or an `Indexes` entry; an entry that leaves one out takes the shared value, and unset keeps the client's default. The options validators check them at startup, naming the setting: `RequestTimeout` must be greater than 0 and at most `24.20:31:23.647`, the longest timeout `HttpClient` accepts, and `MaxRetries` must not be negative. Typesense's existing `RequestTimeout` is now validated too: it must not be negative or longer than `24.20:31:23.647`, and `00:00:00` still means no timeout. Behavior change: a negative Typesense `RequestTimeout`, which used to mean no timeout, now fails startup validation, and so does one longer than `24.20:31:23.647`, which used to fail every request. `AddElasticSearch`, `AddOpenSearch`, `AddMeilisearch` and `AddTypesense` take a new optional `configureClient` parameter (`Action<ElasticsearchClientSettings>`, `Action<ConnectionSettings>` and `Action<HttpClient>`), run on each client after the options are applied, once per cached client. The timeout and retry count are part of the client cache key, so indexes with different values get different clients. Adding the parameter changes the signature of those four public methods, so code compiled against an earlier beta must be recompiled.

- [#143](https://github.com/bielu/bielu.bettersearch/pull/143) [`3ce0941`](https://github.com/bielu/bielu.bettersearch/commit/3ce09410c931b3af395f839fd7bedacba67b8077) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Add `GetDocumentAsync(index, id)` and `CountAsync(query)` to `ISearchProviderAsync` and `ISearchServiceAsync`, and `UpdateDocumentAsync(index, id, fields)` to `IIndexingProviderAsync` and `IIndexingServiceAsync`, as default interface members (#99), so existing implementers still compile and return a failed `Result` naming themselves. `GetDocumentAsync` returns `null` for a missing document or index. `CountAsync` is exact: `_count` on Elasticsearch and OpenSearch, a filtered document fetch on Meilisearch, and every match on Lifti. `UpdateDocumentAsync` replaces the named fields and keeps the others, returning `false` for a missing document or index: a partial `_update` on Elasticsearch and OpenSearch, after checking the index exists, and a read and a whole write on Meilisearch. Lifti keeps no stored fields, so its get and update return a failed `Result`. With the search cache added, `UpdateDocumentAsync` evicts the index's cached searches as the other writes do, and `GetDocumentAsync` and `CountAsync` go to the provider each time, uncached. With indexes routed to keyed providers, all three run on the provider routed for their index.

- [#73](https://github.com/bielu/bielu.bettersearch/pull/73) [`07f5aa1`](https://github.com/bielu/bielu.bettersearch/commit/07f5aa19865feace4e864dfa60cb8c36075417f4) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Elasticsearch: the client factory keys its clients on the connection string and authentication an index resolves to, as the OpenSearch provider does, instead of on the index name. Indexes with the same connection share one client, index names match whatever their case, an index named `default` can no longer collide with the shared client, and a changed connection string or password in `IOptionsMonitor` gets a new client on the next call instead of after a restart. Client creation no longer caches an exception, so invalid settings fail each call until they are fixed. Resolving an index's settings never writes into the stored options.

  Breaking: `IElasticSearchClientSettingsManager.GetOrCreateClientSettings` is replaced by `GetConnectionSettings(indexName)`, which returns the merged settings as a new `ElasticSearchIndexSettings`, and `CreateClientSettings(settings)`. `ElasticsearchClientFactory` no longer takes `IOptionsMonitor<ElasticSearchOptions>`. `ElasticSearchIndexSettings.AuthenticationType` is now nullable: an `Indexes` entry that leaves it unset takes the shared authentication, including an entry with its own `ConnectionString`, which before used no authentication. Set `"AuthenticationType": "NONE"` on the entry to keep the old behavior.

- [#158](https://github.com/bielu/bielu.bettersearch/pull/158) [`f0d8a58`](https://github.com/bielu/bielu.bettersearch/commit/f0d8a584d8d020f0c7a4b9674b5e8816a11fd2a0) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Elasticsearch and OpenSearch take several nodes of a cluster (#150). `AdditionalNodes`, in `SharedIndexSettings` or an `Indexes` entry, lists the cluster's other nodes beside `ConnectionString`, named and shaped as on Typesense, and a request that can't reach a node is sent to the next one. An `Indexes` entry with its own `ConnectionString` uses only its own nodes; one without takes its own `AdditionalNodes` if set, or the shared ones. The new `PoolType` (`NodePoolType`, in `Bielu.BetterSearch.Abstractions.Configuration`) is `Static`, `Sticky` or `Sniffing`, and an `Indexes` entry that leaves it out takes the shared one. Unset, a lone `ConnectionString` still uses a single node pool, as before, and with `AdditionalNodes` the pool is `Static`. Elasticsearch's `CLOUD` and `CLOUDAPI` authentication still connect by the cloud id and don't use either setting.

  The options validators and each call check every additional node as they check `ConnectionString`, and that it uses the same scheme, which the clients require, naming its position, such as `Bielu:BetterSearch:OpenSearch:SharedIndexSettings:AdditionalNodes:1`, and reject an undefined `PoolType`. An `Indexes` entry that sets only `AdditionalNodes` or `PoolType` is now checked after merging, as one with its own connection string or authentication is. Clients are cached per connection string, additional nodes, pool type and authentication, so indexes that differ only in their nodes or pool type get separate clients.

- [#142](https://github.com/bielu/bielu.bettersearch/pull/142) [`92cebce`](https://github.com/bielu/bielu.bettersearch/commit/92cebcec461cd81ee682984d09d53f86d7b6cc3c) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Rebuild an index without downtime, and prefix index names (#22). The new `IIndexLifecycleServiceAsync`, registered by `AddBetterSearch` unkeyed and under each provider key, runs a rebuild through the optional `IIndexLifecycleProviderAsync`: `StartRebuildAsync` creates a new index with the configured `Mappings`, `IndexRebuildDocumentsAsync` fills it (checking the whole batch first, as `IndexMultipleDocumentsAsync` does, and rejecting a document for another index), `CompleteRebuildAsync` points an alias named like the index at it and deletes the indexes the alias pointed at before in one atomic aliases request, and `AbortRebuildAsync` deletes the new index. A rejected step leaves the alias where it was; a step the engine does not acknowledge in time fails but may still apply, so call it again. With the search cache added, `CompleteRebuildAsync` evicts the rebuilt index's cached searches, and facet searches on Elasticsearch, OpenSearch and Meilisearch use the prefixed index too. With indexes routed to keyed providers, the unkeyed `IIndexLifecycleServiceAsync` runs each rebuild on the provider routed for its index.

- [#59](https://github.com/bielu/bielu.bettersearch/pull/59) [`7c6b5e8`](https://github.com/bielu/bielu.bettersearch/commit/7c6b5e82cf6af70306b005a78dd80b290af782c6) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - `IIndexingServiceAsync` observers follow the `IObserver` contract (#56). The `SearchDocument`, `DeleteDocumentRequest` and `DeleteAllDocumentsRequest` streams now behave the same way: `OnNext` is sent once after each operation the provider completed successfully, a rejected document or failed operation sends nothing (the returned `Result` carries the reason), `OnError` is never sent, and `OnCompleted` is sent once, when `IndexingServiceAsync` is disposed. Before, a rejected document sent `OnCompleted` while later documents still sent `OnNext`, `OnNext` for an index or delete was sent before the provider ran, even when it then failed, and deletes sent `OnCompleted` after every call. Subscribing and unsubscribing are thread-safe; observers are called one at a time, and never after `OnCompleted`, only while a service instance is not used concurrently, otherwise an observer must be thread-safe. An observer that throws is logged through `ILogger` and skipped instead of failing the operation or skipping the other observers, `Dispose` never throws, subscribing after disposal completes the observer straight away, and a duplicate subscription stays active until each of its handles is disposed. `SearchServiceAsync` follows the same contract for its `ISearchModel` stream. Breaking: `IIndexingServiceAsync` and `ISearchServiceAsync` now extend `IDisposable`, so a custom service set through `SetIndexingServiceType<T>()` or `SetSearchServiceType<T>()` must implement `Dispose`; `IndexingServiceAsync` and `SearchServiceAsync` use the `protected virtual Dispose(bool)` pattern and take an optional `ILogger`. The DI scope owns both services: don't dispose an injected service, dispose the handle `Subscribe` returned. `Unsubscriber<T>` is no longer used by BetterSearch and is marked `[Obsolete]`; it will be removed before the stable release.

A repeated key, a key differing only in case, the same provider added twice in one `AddBetterSearch` call, and a default that names no registered key now throw at registration. `SetSearchProviderType<T>()` and `SetIndexingProviderType<T>()` now set the unkeyed providers only when no provider is added with `AddProvider`; before, the last call won. - [#132](https://github.com/bielu/bielu.bettersearch/pull/132) [`6c4fe87`](https://github.com/bielu/bielu.bettersearch/commit/6c4fe8729d8c4dbe065933a849833d265687058f) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Meilisearch's `IndexMultipleDocumentsAsync` adds each index's documents in tasks of at most the new `BulkBatchSize` index setting (1000 by default, in `SharedIndexSettings` or an `Indexes` entry), one after another, so a large import is no longer one request; it used to send them all in one task. The setting counts documents, not bytes, so each task must still fit the server's payload size limit: lower it when documents are large. A Meilisearch option made invalid by a configuration reload gives a failed `Result` naming the setting rather than an `OptionsValidationException`. A `BulkBatchSize` of 0 or less fails startup validation, which the Meilisearch options now run (`ValidateOnStart`).

- [#82](https://github.com/bielu/bielu.bettersearch/pull/82) [`d258a92`](https://github.com/bielu/bielu.bettersearch/commit/d258a925c9f55d14668702fef61dac3b5a8d758a) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - The Meilisearch provider now translates `LuceneSubQuery` instead of failing it (#34). The string is parsed with Lucene.NET's `QueryParser` (`Lucene.Net.QueryParser` 4.8.0-beta00018, a prerelease, referenced by `Bielu.BetterSearch.Meilisearch` only) and turned into one filter: field terms, a trailing `*` prefix, ranges (numbers and ISO 8601 dates also compare as such), `_exists_:field`, `field:*` and `AND`/`OR`/`NOT`/`+`/`-` translate exactly. - [#14](https://github.com/bielu/bielu.bettersearch/pull/14) [`a311a64`](https://github.com/bielu/bielu.bettersearch/commit/a311a6402f858306fdae6c6e53dbb9582e193d86) Thanks [@tessl-app](https://github.com/apps/tessl-app)! - Add `Bielu.BetterSearch.Meilisearch`, a Meilisearch provider registered with `AddMeilisearch()`.
