Date query values are now written as ISO 8601 text in UTC, with fractional seconds only when they are not zero (`2026-11-08T13:05:00Z`, `2026-11-08T13:05:00.123Z`), instead of `11/08/2026 13:05:00` (#65). A local `DateTime` and a `DateTimeOffset` are converted to UTC, a `DateTime` with `Kind.Unspecified` is taken as UTC, and a `DateOnly` is `2026-11-08`. Elasticsearch, OpenSearch and Meilisearch now also store date field values as that text, so a term, terms or prefix query with a date value matches the stored date on a keyword field, and a date comes back from a search in UTC rather than with the offset or `Kind` it was indexed with; re-index documents indexed before this version. Lifti indexes and queries dates as that text too, so a date's words are now `2026`, `11`, `08T13`, `05` and `00Z`: a whole date still matches, but a term for its day (`08`) no longer does. A fuzzy query whose value is not a string or a number, such as a date or a boolean, now returns a failed `Result` on Elasticsearch and OpenSearch, as it did before #46, instead of sending the value as text.
