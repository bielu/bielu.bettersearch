Add an opt-in search result cache (#119). `ISearchResultCache`, in Abstractions, is the injection point: `Configurator.AddSearchCache<TCache>()` registers your own, `AddMemorySearchCache()` registers the built-in `MemorySearchResultCache` over `IMemoryCache` (single node only), and the new `Bielu.BetterSearch.Caching.FusionCache` package adds `AddFusionSearchCache()`, an adapter over `IFusionCache` that needs a backplane when the application runs on several nodes. `SearchServiceAsync` caches successful searches under a key built from the provider, `SearchCacheOptions.KeyPart` and the whole query, tagged with the index; failed and cancelled searches are not cached, and observers are notified on a cache hit too. `IndexingServiceAsync` evicts an index's cached searches after every write to it, failed writes included. `SearchCacheOptions` sets the duration (30 seconds by default), per-index `Enabled`, `Duration` and `Tags`, and a `Skip` delegate. Without a registered cache nothing changes. `SearchServiceAsync` and `IndexingServiceAsync` take the cache, and `SearchServiceAsync` its options, as new optional constructor parameters, which keeps source compatibility but changes the constructors' binary signature. Core now references `Microsoft.Extensions.Caching.Memory` and `Microsoft.Extensions.Options`. See the new Caching page.
