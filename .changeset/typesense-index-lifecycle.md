Typesense: `IndexPrefix` and index rebuilds through collection aliases (#147). `TypesenseOptions.IndexPrefix` is put before every collection name the provider sends, for indexing, search, get, count, update, removal, remove all, exists, create, delete and rebuilds; it is not validated, as Typesense accepts any collection name. `TypesenseIndexingProviderAsync` now implements `IIndexLifecycleProviderAsync`: start creates a new collection, complete points a collection alias named like the index at it, deletes the collection it pointed at before and then every other rebuild collection of the index, and abort deletes the new collection unless the alias points at it. The steps are separate requests, as Typesense has no atomic or conditional alias update, so Typesense rebuilds have a single-writer contract: one rebuild of an index at a time, with no two of its calls running at once. The first rebuild of a plain collection deletes it before creating the alias, so searches in between fail. Behavior change: `DeleteIndexAsync` on a name that is an alias deletes the collection behind it and the alias. Test bases: `IndexPrefixTestBase` gains `HasFacets`, `IndexLifecycleTestBase.RemovePendingAliasAsync` is renamed `BeginAbortAsync`, and `IndexLifecycleTestBase` gains `OverlappingCallsSkipReason`, which skips its tests of overlapping calls.
