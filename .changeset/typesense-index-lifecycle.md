Typesense: `IndexPrefix` and index rebuilds through collection aliases (#147). `TypesenseOptions.IndexPrefix` is put before every collection name the provider sends, for indexing, search, removal, remove all, exists, create, delete and rebuilds; it is not validated, as Typesense accepts any collection name. `TypesenseIndexingProviderAsync` now implements `IIndexLifecycleProviderAsync`: start creates a new collection, complete points a collection alias named like the index at it and then deletes the collection it pointed at before, and abort deletes the new collection. The steps are separate requests, as Typesense has no atomic alias swap, and the first rebuild of a plain collection deletes it before creating the alias, so searches in between fail. The first complete or abort of a rebuild records its decision by creating a `<new collection>-decision` collection, so a complete and an abort never both take effect; a complete that finds another complete's decision waits up to 5 seconds for it and then finishes the move itself. Behavior change: `DeleteIndexAsync` on a name that is an alias deletes the collection behind it, its decision collection and the alias. Test bases: `IndexPrefixTestBase` gains `HasFacets` and `HasGetCountAndUpdate`, and `IndexLifecycleTestBase.RemovePendingAliasAsync` is renamed `BeginAbortAsync`.
