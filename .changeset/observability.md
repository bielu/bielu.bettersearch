"bielu-bettersearch": minor

Add observability (#103). `SearchServiceAsync` and `IndexingServiceAsync` now start one OpenTelemetry span per call on the `Bielu.BetterSearch` `ActivitySource` (`search`, `get`, `count`, `index`, `bulk index`, `update`, `remove`, `bulk remove`, `remove all`), tagged with the operation, index, provider, outcome, page and page size, hit count, total count and document count but never query values or document contents. A failed `Result` or an exception sets the span status to `Error` and `error.type` to the error's or exception's type. Error messages can quote the query, so by default they are not recorded: the span status has no description and the log line names the error type only. The new `BetterSearchInstrumentationOptions.RecordErrorMessages` (default `false`, bound from `Bielu:BetterSearch:Instrumentation`) records the first error's message on the span and in the log, and attaches the exception to the `Error` log. A `Bielu.BetterSearch` `Meter` records operation duration, operation count by outcome, and documents indexed, updated and removed (the bulk and remove-all counts; a single `RemoveDocumentAsync` is not counted, and an `UpdateDocumentAsync` that returns `false` for a missing document counts nothing). A failed `Result` is now logged at `Warning`, and an exception other than cancellation at `Error` before it is rethrown, through source-generated `LoggerMessage` methods. With a search cache, a cache hit is not recorded, as it never reaches `SearchServiceAsync`; a routed call records one span from the provider it is routed to. The `SearchServiceAsync` and `IndexingServiceAsync` constructors gain an optional `IOptionsMonitor<BetterSearchInstrumentationOptions>` parameter, a binary break for code that calls them directly, which must be recompiled. New packages: `Bielu.BetterSearch.OpenTelemetry` with `AddBetterSearchInstrumentation()` for `TracerProviderBuilder` and `MeterProviderBuilder`, and `Bielu.BetterSearch.HealthChecks` with `AddBetterSearchHealthCheck()`; without `providerKey`, when two or more providers are registered and none is the default, the check reports its failure status naming the registered keys. `ISearchProviderAsync` gains `PingAsync(index, cancellationToken)` with a default implementation that returns a failed `Result`, so existing implementers still compile; Elasticsearch and OpenSearch send `HEAD /`, Meilisearch and Typesense call `GET /health`, and Lifti always succeeds.
