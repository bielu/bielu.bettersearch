Add observability (#103). `SearchServiceAsync` and `IndexingServiceAsync` now start one OpenTelemetry span per call on the `Bielu.BetterSearch` `ActivitySource` (`search`, `index`, `bulk index`, `remove`, `bulk remove`, `remove all`), tagged with the operation, index, provider, outcome, page and page size, hit count and document count but never query values or document contents; a failed `Result` sets the span status to `Error` with the first error's message. A `Bielu.BetterSearch` `Meter` records operation duration, operation count by outcome, and documents indexed and removed. A failed `Result` is now logged at `Warning`, and an exception other than cancellation at `Error` before it is rethrown, through source-generated `LoggerMessage` methods. New packages: `Bielu.BetterSearch.OpenTelemetry` with `AddBetterSearchInstrumentation()` for `TracerProviderBuilder` and `MeterProviderBuilder`, and `Bielu.BetterSearch.HealthChecks` with `AddBetterSearchHealthCheck()`. `ISearchProviderAsync` gains `PingAsync(index, cancellationToken)` with a default implementation that returns a failed `Result`, so existing implementers still compile; Elasticsearch and OpenSearch send `HEAD /`, Meilisearch calls `GET /health`, and Lifti always succeeds.
