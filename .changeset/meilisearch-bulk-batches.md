"bielu-bettersearch": minor
---

Meilisearch's `IndexMultipleDocumentsAsync` adds each index's documents in tasks of at most the new `BulkBatchSize` index setting (1000 by default, in `SharedIndexSettings` or an `Indexes` entry), one after another, so a large import is no longer one request; it used to send them all in one task. The setting counts documents, not bytes, so each task must still fit the server's payload size limit: lower it when documents are large. An index's documents split into several tasks are no longer all or nothing: the first task that fails stops that index's import, the tasks before it stay stored, other indexes in the same call are still written, and the error's `ids` metadata holds every document not confirmed as stored, while its message separates the documents already stored, the failed task's (stored none, or may still index them after a `TaskTimeout`, with its `taskUid`) and the index's ones not sent. An index whose documents fit in one task behaves as before. A Meilisearch option made invalid by a configuration reload gives a failed `Result` naming the setting rather than an `OptionsValidationException`. A `BulkBatchSize` of 0 or less fails startup validation, which the Meilisearch options now run (`ValidateOnStart`).
