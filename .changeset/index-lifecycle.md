Rebuild an index without downtime, and prefix index names (#22). The new `IIndexLifecycleServiceAsync`, registered by `AddBetterSearch` unkeyed and under each provider key, runs a rebuild through the optional `IIndexLifecycleProviderAsync`: `StartRebuildAsync` creates a new index with the configured `Mappings`, `IndexRebuildDocumentsAsync` fills it (checking the whole batch first, as `IndexMultipleDocumentsAsync` does, and rejecting a document for another index), `CompleteRebuildAsync` points an alias named like the index at it and deletes the indexes the alias pointed at before in one atomic aliases request, and `AbortRebuildAsync` deletes the new index. A failed step leaves the alias where it was. The Elasticsearch and OpenSearch indexing providers implement it; on Meilisearch and Lifti every call returns a failed `Result`. A new `IndexPrefix` option on `ElasticSearchOptions`, `OpenSearchOptions` and `MeilisearchOptions` is put before every index name the provider sends to the server, for indexing, search, removal, remove all, exists, create, delete and rebuilds; Elasticsearch and OpenSearch reject an invalid prefix at startup. Behavior changes: on Elasticsearch and OpenSearch, `DeleteIndexAsync` on a name that is an alias deletes the indexes behind it (one more request per call to look the alias up). Breaking: `IndexSettings.AliasingEnabled`, which nothing read, is removed; the index name is the alias after a rebuild. New public API: `IIndexLifecycleProviderAsync`, `IIndexLifecycleServiceAsync`, `IndexLifecycleServiceAsync`, `IndexRebuild`, the `IndexPrefix` options and `IElasticSearchClientSettingsManager.GetIndexName`, which has a default implementation that adds no prefix, so existing implementers still compile but ignore `IndexPrefix` until they implement it.
