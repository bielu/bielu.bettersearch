Implement facets and aggregations (#20). `ISearchResult` gains `Aggregations`, the results of `FacetQueries` in query order, and `IBucket` gains `Aggregations`, a bucket's nested results; both have a default implementation returning no entries, so existing implementers keep compiling. `BaseSearchResults`, `KeyBucket` and `SingleBucket` implement them, and `KeyBucket.SubBuckets` and `SingleBucket.SubBuckets` now start as an empty list instead of `null`. `TermAggregation` and `MultiTermAggreation` gain `Size`, the number of buckets, 10 when it is 0 (`TermAggregation.DefaultSize`), and the fluent API gains `WithSize` on both. `RetrieveBucketAggregation` and `RetrieveSingleAggregation` read a facet by name from a result or from a bucket's aggregations. Elasticsearch and OpenSearch now run term (`terms`), multi-term (`multi_terms`) and filter facets, nested inside each other, instead of failing; a field mapped as `Text` is counted on its `keyword` sub-field, and a facet on an unmapped text field fails with a message saying to map it or facet on `Field.keyword`. Meilisearch now runs top-level term facets through `facetDistribution`, with a second search without the post filter when the query has one, and fails a multi-term, filter or nested facet, and a facet whose field has 100 or more values (`maxValuesPerFacet`). Counts cover the main query's matches: a post filter narrows the hits but not the counts. Every provider fails a `null` facet, a facet without a name, two facets of the same name at one level, a term facet without a field, a multi-term facet with fewer than two fields, a `Size` below 0 or above 65,536, and an unknown facet type, before asking the engine. Breaking: Lifti used to ignore `FacetQueries` and now returns a failed `Result`.
