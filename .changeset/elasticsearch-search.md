Implement search in the Elasticsearch provider. `SearchAsync` translates every sub-query type (bool, term, terms, prefix, prefix phrase, fuzzy, numeric, long, date and string ranges, raw Lucene, geo distance), applies `Page`, `PageSize`, `SortOrder`, `Properties` and post filters, and maps hits with their id, score, type and fields. Server errors and unsupported facets and highlighting return a failed `Result`. The translator is now `IQueryTranslateServiceAsync<Query>` with one `ISubQueryTranslator<Query>` per sub-query type, `ISearchModel` gains `Score`, and `SearchServiceAsync` returns a provider's failed `Result` instead of throwing.

`BoolSearchSubQuery.Add` now sets the clause's occurrence instead of dropping it, and Lifti combines clauses with the same Lucene semantics as Elasticsearch: `SHOULD` next to a `MUST` no longer widens the result, `FILTER` acts as `MUST`, and `MUSTNOT` with no positive clause anywhere in the query returns a failed `Result`, while a nested bool with only `MUSTNOT` clauses excludes from its parent's matches. Lifti hits now carry `Score`. In Elasticsearch, `TermsQuery` is one `terms` query, post filters are translated through the new `IPostFilterTranslateServiceAsync<T>`, the client factory is a singleton that reuses one client per connection, a page past `ElasticSearchOptions.MaxResultWindow` returns a failed `Result`, the total hit count is exact up to `MaxResultWindow`, a `terms` query past `index.max_terms_count` returns a failed `Result`, hit fields keep their JSON types, and only known metadata fields such as `_id` skip the `fields.` prefix.

Breaking: `ISearchModel` gains `Score`, so an implementation outside this library must add it, and `ElasticSearchSearchProviderAsync` takes `IPostFilterTranslateServiceAsync<Query>` and `IOptionsMonitor<ElasticSearchOptions>` in its constructor.
