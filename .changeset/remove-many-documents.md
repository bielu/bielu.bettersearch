Add `RemoveDocumentsAsync(index, ids)` to `IIndexingServiceAsync` and `IIndexingProviderAsync`, removing many documents in one call (#19). It returns how many documents were removed: an id that is not in the index is not counted and is not an error, a repeated id is removed once, and an empty list succeeds with 0 without calling the engine. A `null` list, or a `null` or empty id, is a failed `Result` and removes nothing. Elasticsearch and OpenSearch send one bulk request; when some items fail, the `Result` fails with a message naming up to 20 failing ids, the error's `ids` metadata holding all of them, and the other documents are already removed. Meilisearch sends one deletion task, which succeeds or fails as a whole, and keeps Meilisearch's error code in the `code` metadata. Lifti removes the ids one by one. A missing index is a failed `Result` on Elasticsearch, OpenSearch and Meilisearch, and success with 0 on Lifti, as with `RemoveDocumentAsync`. On success, the service sends one `DeleteDocumentRequest` to its observers for each distinct id; a failed `Result` sends nothing. Breaking: a custom `IIndexingServiceAsync` or `IIndexingProviderAsync` must implement the new method.
