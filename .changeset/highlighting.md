Implement highlighting (#21). `ISearchHit` gains `Highlights`, the marked fragments of each field keyed by field name, with a default implementation returning no entries, and `SearchHit` takes them as an optional constructor argument; matched terms sit between `<em>` and `</em>` (`SearchHit.HighlightPreTag` and `HighlightPostTag`), and the rest of the text is HTML-escaped. Elasticsearch and OpenSearch now run `HighlightQueries` instead of failing: one field, or every field with `IsAllField`, highlighted where the main query matched it, or where the request's own `Queries` match. A multi-valued field returns only the values that matched, a hit with nothing marked has no entries, and a `null` entry, an entry with neither `Field` nor `IsAllField`, two entries for the same field, also under different names for it (`Name` and `fields.Name`), or a `null` clause in a request's own `Queries` return a failed `Result`. Meilisearch still returns a failed `Result`, now saying why: Meilisearch marks only search text matches and the provider runs every query as a filter. Breaking: Lifti used to ignore `HighlightQueries` and now returns a failed `Result`, as its index keeps no document text to mark. `HighLighterConfigurator` now adds the request it configures to the query, rather than a `null` entry.
