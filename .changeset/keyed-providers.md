Support more than one provider in a container (#100). Each provider extension now registers its provider under a key, its name by default (`AddElasticSearch(key: "products")` to choose one), and `AddBetterSearch` registers a keyed `ISearchProviderAsync`, `IIndexingProviderAsync`, `ISearchServiceAsync`, `IIndexingServiceAsync` and `IDocumentValidatorAsync` for each key, resolved with `[FromKeyedServices("products")]`. Each keyed service is its own instance with its own observers; its validator is the unkeyed one unless one is registered for that key. With one provider the unkeyed services work as before. Behavior change: with two or more providers, the unkeyed services used to resolve to the last provider added; resolving them now throws an `InvalidOperationException` that lists the registered keys, unless `Configurator.SetDefaultProvider(key)` picks one. A repeated key, a key differing only in case, the same provider added twice in one `AddBetterSearch` call, and a default that names no registered key now throw at registration. `SetSearchProviderType<T>()` and `SetIndexingProviderType<T>()` now set the unkeyed providers only when no provider is added with `AddProvider`; before, the last call won. New public API: `Configurator.AddProvider<TSearchProvider, TIndexingProvider>(key)`, `Configurator.SetDefaultProvider(key)`, `SearchApplicationConfiguration.ProviderKeys` and `DefaultProviderKey`, a `key` parameter and a `DefaultKey` constant on each provider extension.
