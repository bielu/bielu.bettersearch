Give the query model one source of truth for a clause's occurrence, one shape for every clause list, and stricter value types (#163). Breaking: code that uses the old shapes stops compiling until it is updated.

- A clause's occurrence now lives on the sub-query only. `ISearchQuery.Query` was an `IDictionary<Occurrence, List<ISearchSubQuery>>` whose key decided the occurrence and ignored the sub-query's own `Occurrence`; it is now an `IList<ISearchSubQuery>`, and every provider combines each clause by its own `Occurrence`, as inside a bool. `SearchQuery.Add(occurrence, subQuery)` now sets `subQuery.Occurrence`, as `BoolSearchSubQuery.Add` already did, so `query.Add(Occurrence.Should, new TermSubQuery { ... })` is a `Should` clause wherever it is placed. A sub-query put straight into a list keeps its own `Occurrence`, `Must` by default.
- The other clause containers take the same shape: `ISearchQuery.PostFilterQuery` (was `IDictionary<Occurrence, List<INestableQuery>>`, bools only) is an `IList<ISearchSubQuery>` and takes any sub-query; `FilterAggregationQuery.Queries` and `IHighlightQuery.Queries` (were `Dictionary<Occurrence, ISearchSubQuery>`, one clause per occurrence) are `IList<ISearchSubQuery>` and hold any number of clauses; `INestableQuery.NestedQueries` is an `IList<ISearchSubQuery>` (was `List<ISearchSubQuery>`). `FilterAggregationQuery` and `IHighlightQuery` gain `Add(occurrence, subQuery)`, which sets the occurrence and appends; `Add` on `SearchQuery`, `BoolSearchSubQuery`, `FilterAggregationQuery` and `BaseHighlightQuery` throws `ArgumentNullException` for a `null` sub-query (`SearchQuery.Add` and `BoolSearchSubQuery.Add` used to store it); `IHighlightQuery` now extends `ICreatableSearchQuery`, so its implementers need that method.
- `ISearchSubQuery.BoostValue` is a `double` (was `int`), so a boost of 0.5 or 1.5 can be set; Elasticsearch and OpenSearch send it as given, and both hold it as a 32-bit float, so a positive boost that a float can't hold (`1e100` would become infinity, `1e-100` would become 0) returns a failed `Result` naming `BoostValue` instead of being sent. The fluent API's `WithBoost` takes a `double` and also throws `ArgumentOutOfRangeException` for a boost that is not a finite number.
- `SpatialSearchSubQuery.UnitOfDistance` is a new `DistanceUnit` enum (was a `string`): `Kilometers` (the default, as before), `Meters`, `Centimeters`, `Millimeters`, `Miles`, `Yards`, `Feet`, `Inches` and `NauticalMiles`, the units every provider accepted. A value outside the enum returns a failed `Result` naming `UnitOfDistance`. The fluent API's `WithUnitOfDistance` takes a `DistanceUnit`.
- `SearchQuery.Properties` is empty by default (was `null`); empty returns every field, as `null` did, on every provider.
- The highlight error for a `null` clause in a request's own `Queries` now reads "holds a null clause." without the occurrence.
- The search result cache key now includes clause order, as `Query` is a list: two queries that add clauses of different occurrences in a different order no longer share a cache entry.
