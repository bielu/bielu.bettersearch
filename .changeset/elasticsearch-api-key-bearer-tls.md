Elasticsearch gets two authentication types for a cluster at `ConnectionString`: `APIKEY`, which sends `AuthenticationDetails:ApiKey` (the `encoded` value of a created key) as `Authorization: ApiKey`, and `BEARER`, which sends the new `AuthenticationDetails:Token`, such as a service account token, as `Authorization: Bearer`. Elasticsearch and OpenSearch get two TLS index settings: `CertificateFingerprint`, the SHA-256 fingerprint of the server's certificate or of a CA in its chain, so a cluster with a self-signed certificate, such as a default Elasticsearch 8 or later install, can be reached without turning TLS off, and `DevelopmentOnlySkipCertificateValidation`, which accepts any certificate and is meant for local development only. The TLS settings go with the connection string: an `Indexes` entry with its own `ConnectionString` uses only its own, and one that sets a TLS setting without its own `ConnectionString` fails validation. Startup validation names the missing `ApiKey`, `Token` or `ConnectionString` for the new types, rejects a fingerprint that is not 64 hex digits and one set together with the skip switch, and the client cache key includes the new settings while its `ToString()` still leaves out every credential. The new enum values are added after the existing ones, so their numbers don't change.
