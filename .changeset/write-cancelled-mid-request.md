Every Elasticsearch and OpenSearch indexing method now throws `OperationCanceledException` when its `CancellationToken` is cancelled while the request is in flight (#79). With `ThrowExceptions` off, the clients report such a request as a response with no status code. Before, only `IndexExistsAsync` and `RemoveDocumentsAsync` threw, and so did `EnsureIndexExistsAsync` when its exists check was cancelled. `IndexDocumentAsync`, `IndexMultipleDocumentsAsync`, `RemoveDocumentAsync`, `RemoveAllDocumentsAsync`, `DeleteIndexAsync` and OpenSearch's `CreateIndexAsync` returned a failed `Result` built from the client's debug information. Elasticsearch's `CreateIndexAsync` returned a successful `Result<bool>` holding `false`. `EnsureIndexExistsAsync` cancelled during its create request returned what `CreateIndexAsync` returned. A request that returns after its token was cancelled now throws too, even when the server answered, so a write cancelled after the server received it may still have been applied.
