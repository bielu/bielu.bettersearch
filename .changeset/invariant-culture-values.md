Query values are turned into text the same way on every machine (#33). The Elasticsearch and OpenSearch Prefix and PrefixPhrase translators and the Lifti Term, Terms, Fuzzy, Prefix and PrefixPhrase translators used the culture-dependent `ToString()`, so `3.5` was sent as `"3,5"` on a machine running under a culture such as `pl-PL`. They now share one internal helper, which writes numbers and dates with the invariant culture and booleans as `true` or `false`. The OpenSearch Fuzzy translator already used the invariant culture; it now also sends booleans in lower case. The Elasticsearch Fuzzy translator used to send the typed value, so a number went as the JSON number `3.5` and a date failed translation; it now sends text, as OpenSearch does, so a number goes as the string `"3.5"`, which a `match` query treats the same. Lifti also indexes field values with the invariant culture, so indexing and querying follow the same rule. Lifti splits that text into words at punctuation, though, so a query for a decimal such as `3.5`, or a whole date, still matches nothing there, and a fuzzy one for a decimal can match a nearby number; the feature matrix and the Lifti page say so.
