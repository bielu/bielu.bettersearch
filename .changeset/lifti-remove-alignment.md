Lifti's `RemoveDocumentAsync` now matches Elasticsearch on errors (#53): a cancelled token throws `OperationCanceledException` instead of returning a failed `Result`, and an exception caught during removal becomes a failed `Result` that keeps it as its cause (a failed index lookup is still returned with the index manager's own errors). The index to remove from now comes from the registered `IClientFactoryAsync<IFullTextIndex<string>>`, like every other Lifti write, so a custom or decorated factory is honoured. `ILiftiIndexManager.GetIndexAsync` is now a required member with no default implementation; a custom index manager must implement it (return `null` for a missing index, without creating it). `RemoveDocumentAsync`, `DeleteIndexAsync` and `RemoveAllDocumentsAsync` now take a lock per index name, shared by every provider on the same index manager, so a concurrent `DeleteIndexAsync` can no longer make `RemoveDocumentAsync` create the deleted index again. `RemoveAllDocumentsAsync` also lets cancellation propagate instead of returning it as a failed `Result`.
